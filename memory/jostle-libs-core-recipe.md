For [[jostle-libs-project]] — how `bc-jostle-libs/core` was assembled to compile green (1590 files, jar `bccore-jsl-1.0-SNAPSHOT.jar`). See [[jostle-libs-core-closure]] for why.

Recipe (sources from bc-java 1.85-SNAPSHOT):
1. Copy `bc-java/core/src/main/java/org` wholesale (self-contained bccore: asn1, util, math, crypto, internal, i18n, iana, + bouncycastle).
2. Overlay `bc-java/prov` support packages: `jcajce` and `jce`. Do NOT copy `x509` (needs ldap; no satellite import) or prov `ldap`/`pqc`.
3. **Delete the BC software-provider engine layer** (jostle replaces it):
   - `jce/provider/*` (replaced by a shim — see below), `jcajce/provider/*` EXCEPT keep `config`, `util`, and `asymmetric/util` + `asymmetric/dh`. (NOTE 2026-06-08: `crypto.ec.ECUtil` — formerly cited here as the reason to keep this EC support — was package-private and unreferenced and has since been REMOVED; `crypto.ec` now holds only `CustomNamedCurves`.)
4. **Remove PQC** (jostle owns PQC via OpenSSL): delete `pqc/` entirely; delete software ML-DSA/ML-KEM/SLH-DSA engines under `crypto/signers/{mldsa,slhdsa}`, `crypto/kems/mlkem`, the signer/kem wrappers (`HashSLHDSASigner`, `SLHDSASigner`, `HashMLDSASigner`, `MLKEMGenerator`, `MLKEMExtractor`), and the PQC param/key family in `crypto/params` + `crypto/generators` (`ML*`,`SLHDSA*`). Delete jcajce composite-sig keys (`CompositePublicKey/PrivateKey/CompositeUtil/ExternalPublicKey/MLDSAProxyPrivateKey`).
5. **Patch the two low-level key factories** `crypto/util/{SubjectPublicKeyInfoFactory,PrivateKeyInfoFactory}.java`: brace-aware-strip the `else if (... instanceof <ML/SLHDSA/HSS/LMS>...)` branches and their imports. After stripping they no longer reference `Utils`, so `crypto/util/{Utils,PublicKeyFactory,PrivateKeyFactory,OtherInfoGenerator}.java` are deleted (nothing in kept core needs them; only the satellite `*/bc/*` software paths did).
6. **Write a `BouncyCastleProvider` shim** at `jce/provider/BouncyCastleProvider.java`: extends `Provider` implements `ConfigurableProvider`, `PROVIDER_NAME="BC"`, registers nothing, a trivial `ProviderConfiguration` (null/empty returns), `addAlgorithm/addAttributes/...Converter` impls, and static `getPublicKey/getPrivateKey` returning `null` (JSL supplies keys via JCA, not reconstructed here).

**UPDATE 2026-06-06: `org/bouncycastle/jce/` removed from core entirely (user request), which cascaded into removing the whole BC software-provider machinery:**
- Deleted `core/.../jce/**` and the now-dead `core/.../jcajce/provider/**` (config, util, symmetric, asymmetric engine SPIs) — none of it was referenced by the kept jcajce helpers/specs/io/interfaces or by asn1/util/math/crypto. The `BouncyCastleProvider` shim is gone.
- This drops classic-EC/DH machinery from core (fine — jostle has no EC). Kept: `jcajce/{util (Default/Named/Provider JcaJceHelper), spec, io, interfaces}` + top-level jcajce classes.
- Satellite deltas this forced: **mail** — deleted the `smime/examples/*` files that used `BouncyCastleProvider`; **pg** — `JcaOpenPGPImplementation` default provider `new BouncyCastleProvider()` → `(Provider)null` (JDK default; pass JSL explicitly for PQC), `JceAEADCipherUtil` now builds `GCMParameterSpec` directly (dropped the removed `GcmSpecUtil` shim), `JcaPGPKeyPairGeneratorProvider.generateEC{DH,DSA}KeyPair` now throw (EC out of scope); **tls** — `XDHUtil`/`KemUtil` dropped the dead `instanceof BouncyCastleProvider` fast-path (kept the X.509 fallback), `JceTlsECDomain` dropped the BC-EC `instanceof org.bouncycastle.jce.interfaces.ECPublicKey` branch (kept the JDK `java.security.interfaces.ECPublicKey` branch). util/pkix unaffected.
- Verified: `./gradlew clean build` green; pkix suite 7 pass / 1 skip / 0 fail.

Build: `./gradlew :core:jar`, release 8, default java 17. (Analysis artifacts formerly in `build-analysis/`; that 67MB scratch dir was DELETED — unused by the build, regenerate via the jdeps step in [[jostle-libs-core-closure]] if needed.) NOTE: the `bc` (BcXXX) operator/cert packages in the satellite modules use this software path and will be the documented source deltas (excluded/patched) when building util/pkix — JSL callers use the `jca`/`jce` builder variants with `.setProvider("JSL")`.

**UPDATE 2026-06-06 (b): core was re-derived from bc-java HEAD `c845517fc1` after an accidental `rm -rf` of `core/` (see [[no-rm-rf-relative-traversal]]). Procedure that reproduced the green state, plus the crypto cleanup task:**
- core/build.gradle must be MINIMAL (a comment is enough): root `build.gradle` `subprojects{}` centralises the java plugin, `release=8`, jar/sourcesJar naming (`bccore-jsl`), manifest. The bc-java core/build.gradle (application+jmh, `bccore-$vmrange`, SQIsign jdk1.9 MR overlay, its own sourcesJar) CONFLICTS — do not use it.
- **Remove bc-java's multi-version source roots**: under `core/src/main/`, keep only `java/` (+ `resources/`); delete `j2me`, `jdk1.1`..`jdk25`, `jdk1.9`, `ext-jdk1.9`, `javadoc`. They aren't compiled but otherwise pollute any reference/closure analysis (they reference the engines and keep dead crypto alive).
- Drop bc-java's `core/src/test` wholesale (498 files referencing removed engines/pqc); jostle core ships no unit tests (meaningful tests live in the satellites).
- Structural deletes (move-not-rm): `jce/**`, `jcajce/provider/**`, `pqc/**`, `x509/**`, `ldap/**`. Then compile-error-driven deletes converge: `crypto/util/{Utils,SubjectPublicKeyInfoFactory,PrivateKeyInfoFactory,PublicKeyFactory,PrivateKeyFactory,OtherInfoGenerator,OpenSSHPrivateKeyUtil}`, `crypto/signers/{SLHDSASigner,HashSLHDSASigner,HashMLDSASigner}`, `crypto/kems/MLKEMGenerator`, `jcajce/{CompositePublicKey,CompositePrivateKey,CompositeUtil,ExternalPublicKey,MLDSAProxyPrivateKey}`, `jcajce/util/BCJcaJceHelper`, `jcajce/spec/DSTU4145ParameterSpec`. (No satellite/provider references any of these — verified — so delete beats the old patch-and-keep of the key factories.)
- Stale resources to drop: `META-INF/services/java.security.Provider` (named the removed BC + PQC providers), `resources/org/bouncycastle/{x509,pqc}` trees.
- **Crypto cleanup (the actual task):** remove crypto classes not REACHABLE from real consumers. Use a **closure/reachability** prune, NOT a leaf-prune: leaf-pruning cannot break mutually-referencing dead islands (PQC, bls, the Owl/JPAKE/ECJPAKE PAKEs, hash2curve, kems, encodings, …). Algorithm: roots = crypto type-names occurring in the consumer corpus (satellites + jostle provider + non-crypto core, excluding `**/build/**` and backup dirs); BFS forward over intra-crypto name references; remove every crypto file none of whose declared types are in the closure. CRITICAL: the map must be **name→ALL declaring files** — crypto has duplicate simple names across packages (`Utils` ×several, plus `Builder/Mode/State/Friend/ProcessingBufferType/AsconParameters/SparkleParameters/ECSchnorrZKP/ExposedByteArrayOutputStream`); a name→single-file map wrongly drops e.g. `digests/Utils` (used 68×). Verify with `clean build`; restore-on-failure from the backup dir. Result: crypto 774→**232**; core/src/main/java ≈ 1035. Removed whole packages: `bls, hash2curve, kems, encodings`, the PAKEs, and the PQC families; plus unreferenced engines/digests/params and root interfaces `AsymmetricBlockCipher/DSAExt/StreamBlockCipher/SecretWithEncapsulation/EncapsulatedSecret{Generator,Extractor}`. (A manifest was kept at `build-analysis/crypto-removed-unreachable.txt`, but `build-analysis/` has since been deleted.)
- Verified green-equivalent: `./gradlew assemble` builds all `*-jsl` jars; pkix `test` = 81 run / 3 fail / 1 skip — the 3 fails are the pre-existing ML-DSA CMS `public key mismatch` tests (fail identically on un-pruned core; ML-DSA is delegated to jostle native, absent in lib unit tests).
